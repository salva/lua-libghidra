## Findings

### API-01 — Medium: Session reopen bypasses the facade's rejected-option policy

**Evidence:** [lua/libghidra/init.lua#L8](../../../../lua/libghidra/init.lua#L8) installs `Session:open_program` as a direct lowlevel forwarder. In contrast, the public factory checks its narrower program keys at [init.lua#L105](../../../../lua/libghidra/init.lua#L105). The forwarded parser explicitly accepts `read_only` and `project_name` at [src/owner.cpp#L387](../../../../src/owner.cpp#L387), copies them at [owner.cpp#L531](../../../../src/owner.cpp#L531), and dispatches OpenProgram at [owner.cpp#L606](../../../../src/owner.cpp#L606). [SPEC.md#L223](../../../SPEC.md#L223) says the facade rejects either key because native open ignores them; [SPEC.md#L91](../../../SPEC.md#L91) reserves them to lowlevel.

**Cause/impact:** the initial `gh.open` path enforces the convenience contract, but an existing Session exposes a second opening path with the native grammar. `session:open_program{...,read_only=true}` succeeds without providing read-only behavior. This is a wrapper policy inconsistency, not a request to implement upstream read-only protection. The distinction matters precisely because the explicit native escape hatch is supposed to identify faithful-but-ignored options.

**Reproduced:** a tiny standalone Lua 5.4 process in the existing guest loaded the baseline Lua files and the existing `approved-sdk-prefix` native module, opened the authored ELF, then passed identical program options containing `read_only=true, project_name='ignored'` to both entry points. Output:

```text
factory facade: nil INVALID_ARGUMENT
session facade reopen: /work/lua-libghidra/tests/fixtures/inputs/authored.elf nil
```

The probe used `sudo lxc-attach -n saivage-lua-libghidra -- lua5.4 -`, source `package.path=/work/lua-libghidra/lua/?.lua;/work/lua-libghidra/lua/?/init.lua`, and native `package.cpath=/work/lua-libghidra/.saivage/work/cards/card-e-a/approved-sdk-prefix/lib/lua/5.4/?.so`. Program options used `tests/fixtures/inputs/authored.elf`, `language_id='x86:LE:64:default'`, `compiler_spec_id='gcc'`. It explicitly closed its owner; no state_path or fixture mutation was used. Static source tracing independently establishes the baseline defect; the pre-existing native artifact was not rebuilt or independently provenance-certified during this audit.

**Focused fix:** give `Session:open_program` the same raw key restriction as `gh.open` before forwarding to the shared native owner; preserve the native method's response shape and generation behavior. **Proportionate alternative:** remove the undocumented Session reopen convenience and retain the already documented `session:native():open_program` route. Do not add an upstream read-only implementation.

**Regression:** on an existing Session, reject each ignored key individually (including `read_only=false`) with binding INVALID_ARGUMENT and unchanged generation; retain successful permitted reopen, invalidation of old iterators, and lowlevel acceptance of both ignored fields. **Confidence: high.** Classification: evolutionary facade drift from bulk forwarding, not an intentional native limitation.

### API-02 — Low: Shutdown is a public Session convenience despite native-only disposition

**Evidence:** [init.lua#L8](../../../../lua/libghidra/init.lua#L8) also installs `Session:shutdown`. [M4-FULL.md#L139](../../../M4-FULL.md#L139), particularly line 148, says all full specialist calls, including Shutdown, use native() and none creates a Session convenience; [API.md#L95](../../../API.md#L95) likewise says no new facade convenience is enabled. [SPEC.md#L218](../../../SPEC.md#L218) assigns shutdown to the native escape hatch.

**Cause/impact:** a shipped method and its call-surface documentation disagree. Unlike `Session:close_program`, this convenience forwards save shutdown without the facade state-path guard ([init.lua#L13](../../../../lua/libghidra/init.lua#L13)); a caller discovering the method can reasonably confuse the two convenience policies. The native empty-state-path behavior itself is documented and is not an upstream defect raised here.

**Reproduced:** the same tiny real-owner probe printed `session shutdown exposed: function`. No save shutdown was executed. Native policy behavior is statically traceable through [owner.cpp#L394](../../../../src/owner.cpp#L394) and [owner.cpp#L612](../../../../src/owner.cpp#L612).

**Focused fix:** remove the unintended facade alias to match the explicit specialist disposition. **Proportionate alternative:** explicitly approve and document the existing alias as faithful native shutdown, including its empty-path save caveat; do not silently imply that close_program's stricter policy applies. **Regression:** assert the selected public-surface disposition, plus continued lowlevel Shutdown availability and its `accepted` envelope. **Confidence: high** for the mismatch; no new data-loss experiment is claimed. Classification: historical/evolutionary surface-accounting drift, not missing native coverage.

## Historical baggage versus current defects

The milestone prose contains earlier incomplete states followed by later reconciliations; API explicitly distinguishes proposed inventory syntax from shipped M3/M4 grammar ([API.md#L28](../../../API.md#L28)). This audit used production parsers and the explicit grammar supplements, not old proposed adapters, as evidence of actual availability. The chronological presentation is historical baggage, not proof that an adapter remains absent.

The two findings above are narrower: current Lua forwarding disagrees with current facade policy/disposition. Keeping one shared native converter and a small facade is otherwise appropriate. Numeric dispatch IDs and the repeated handwritten field tables are evolution-sensitive maintenance points, but this review found no mapping defect that justifies a framework rewrite.

DefinedStrings' empty compatibility response, native ignored mutation arguments, unsupported type kinds, type lookup/path surprises, missing native producers, limited state reload and raw FileBytes/extreme-address restrictions remain documented upstream limitations. Do not revive settled upstream fault-injection gates or demand engine repairs to close this audit.

## Limitations and dimension conclusion

This was a static production/API/native-source review plus one isolated, read-only-fixture Lua probe, not a fresh full qualification run. The coordinator owns suite execution. No new persistence save/reload, huge buffer allocation, extreme address, injected native exception, allocator/longjmp or multi-state lifetime experiment was performed; the separate ownership reviewer owns that boundary. Existing test descriptions were not relabelled as newly reproduced passes.

**Conclusion:** operation coverage and included response/request model fidelity are substantially coherent, with intentional upstream constraints generally described honestly. Correct the medium facade reopen policy bypass and reconcile the low Shutdown surface mismatch before calling the API contract internally consistent. Neither finding calls for a new backend, expanded scope or upstream repair campaign.
