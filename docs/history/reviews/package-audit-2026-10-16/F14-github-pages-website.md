# F14 — Static project website on GitHub Pages

Priority: operator-requested feature, added 2026-10-16 during planning.
Category: documentation delivery. Transversality: user docs/site/build validation.

Add a task or subplan to the master plan for a static project website served on
GitHub Pages for `salva/lua-libghidra`. Planning is authorized, not implementation,
push, enabling Pages, modifying repository settings or publishing the site.

The design must provide a simple user-facing landing page and navigation for the
maintained installation, quickstart, API, limitations and notices content. Reuse
the maintained documentation rather than creating a separately drifting manual.
The public site is package documentation for F13: no Saivage references except
optional creation acknowledgment; development plans/history/operator material
must not leak into the built site. Preserve substantive safety and licensing
qualifications, attribution and exact notice availability.

Evaluate a minimal GitHub Pages-native static approach against a proportionate
alternative. Specify source layout, project-site base path, local preview/build,
links/assets validation, generated-field handling, explicit publication inputs,
workflow permissions and separate operator publication prerequisites. Avoid an
application framework, unnecessary JavaScript or a second API/source generator.
Coordinate doc ownership with group B and final sequencing with the master plan.
